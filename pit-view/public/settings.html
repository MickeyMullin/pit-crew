    Self-review over limit

    A review of your own PR may start while the limit is reached, once every review queued before it has started or left the queue. Never more than one at a time.

    Added to every review, re-review, self-review, tandem review, and stack review, unattended auto-reviews included, and a start's Special instructions replace them for that run. Never a Dependabot review or sweep, a Fix session, or an Update session. They can narrow what the reviewer reads, add what to look for, and set emphasis; they never lift --no-post, add a GitHub write, change the report's format or the commit reviewed, or ask for a command to be run. The reviewer reads them from a file, and the report does not show them unless they ask for that. At most 2,000 characters.

    Models

    A JSON object with registry (a list of { id, runner, provider, model } entries, the runner being claude, codex, or hermes), fallback (the id of the pinned fallback), and slots (review and autoReviewHuman each a pair of ids, primary first, and stack, sweep, and autoReviewBot each one id). A model name has no spaces and does not start with a dash. An entry may use a built-in id only to restate that built-in entry exactly. Only those four fields are stored: any other field is dropped, and a field named like a key, secret, token, or password is refused. Empty means the built-in models. A bad entry is set aside on its own, and a slot that names an unknown id takes its built-in default, read from the built-in table, with a warning below. The slots are stored and checked here, and no start reads them yet: a start still uses the models set under Agent and the runner chosen in the drawer. Only Claude and Codex entries can start a run for now. The text the dashboard posts (the Post it offer and the post of a stored report) is refused when it names any model here or in the built-in table, a vendor or runner, a term for AI, or a review mode; a review that posts for itself is governed by the review prompt, not by this check.
